# Локальные журналы

FundingMonitor использует ILogger<T> в модулях и NLog в ApiHost/DatabaseMigrator. Консоль показывает краткие сообщения с местным временем, файлы содержат JSONL: одно событие на строку, время UTC. Seq и другие серверы не требуются.

## Расположение и хранение

По умолчанию относительно каталога сборки приложения (AppContext.BaseDirectory):

- ApiHost: logs/api-host/app.jsonl;
- DatabaseMigrator: logs/database-migrator/app.jsonl.

Абсолютный путь выводится при запуске. Параметр Logging:Directory в конфигурации или переменная среды Logging__Directory переопределяет каталог. Относительный путь считается от каталога сборки, а не текущего рабочего каталога. При одновременном запуске нескольких экземпляров задавайте каждому отдельный каталог.

Новый файл создаётся ежедневно или после 20 МиБ. Сохраняется максимум 20 архивов до 7 дней. Ограничение количества может удалить записи раньше семи дней. Размер является порогом ротации, не строгой квотой: отдельная запись может его превысить. Очистка выполняется при работе NLog, а не при выключенном приложении. Старые текстовые журналы этой настройкой не удаляются.

Конфигурации: src/FundingMonitor.ApiHost/nlog.config и src/FundingMonitor.DatabaseMigrator/nlog.migrator.config. Они копируются при сборке и публикации. Стандартные каталоги logs исключены из Git.

## Поля и уровни

Timestamp, Level, Category, Message, MessageTemplate; Exception при наличии. Контекст по применимости: CycleId, EventId, RequestId, Exchange, Symbol, Attempt, DurationMs. EventId — идентификатор бизнес-события, а не числовой идентификатор ILogger. Attempt начинается с 1.

Information содержит итоги операций и HTTP-запросов. Warning — временные сбои с повтором и ожидаемые ошибки запроса. Error — окончательный провал и подтверждённая DLQ. Debug содержит отдельные события и подробности шлюзов. Штатная отмена не является Error.

Для адресного Debug добавьте правило перед общим FundingMonitor.* в соответствующем XML и перезапустите приложение:

```xml
<logger name="FundingMonitor.HistoricalRates.*" minlevel="Debug" writeTo="file,console" final="true" />
```

Запись о создании события на Debug связывает CycleId с EventId. Outbox и HistoricalRates используют тот же EventId при публикации и повторах. Scope не переносится через RabbitMQ автоматически: потребитель создаёт его из события.

## Просмотр

Откройте файл в редакторе и ищите EventId или символ. Для фильтрации PowerShell (подставьте фактический путь из запуска):

```powershell
Get-Content 'C:\path\to\logs\app.jsonl' |
    ForEach-Object { $_ | ConvertFrom-Json } |
    Where-Object { $_.Exchange -eq 'Binance' } |
    Select-Object Timestamp, Level, Message, EventId
```

При чтении активного файла инструмент должен разрешать совместный доступ для записи. Для анализа можно скопировать закрытый архив. Переносы строки исключения представлены в JSON как экранированные символы.

## Надёжность

Файловая запись асинхронна: очередь до 10000 событий, при переполнении записи отбрасываются, сбор данных не блокируется. При штатной остановке выполняется сброс с таймаутом 5 секунд; аварийная остановка может потерять очередь. Журнал не является гарантированным аудитом.

Внутренние предупреждения NLog выводятся в stderr. Ошибка записи файла не должна останавливать бизнес-операции; неверная конфигурация выявляется при запуске. Пароли, строки подключения, тела HTTP-запросов и полные ответы бирж специально не записываются. Сообщения исключений всё равно требуют осторожности: не включайте в них секреты.

## События по участкам

| Участок | Обычный режим | Debug |
| --- | --- | --- |
| CurrentRates | Итог цикла: ставки, события, успешные/неуспешные биржи, длительность | Создание события с EventId, количество выбранных API записей |
| Outbox | Непустой пакет: attempted/published/failed, длительность; один Warning с исключением при сохранённом повторе | Подтверждённая публикация события |
| HistoricalRates | Итог обработки, запланированный повтор, подтверждённая DLQ, неподтверждённая публикация и переподключение consumer | Подписка воркера |
| ExchangeIntegration | Диагностика неуспешной операции; одно предупреждение при неполном снимке OKX или недоступных интервалах Binance | Параметры страницы истории, длительность операции, детали ошибки/инструмента |
| HTTP | Одна итоговая запись со статусом, временем и исключением при ошибке | Детали бизнес-результата без копирования query string |

Неподтверждённая DLQ не означает, что сообщение уже в DLQ: оригинал остаётся unacked. Сбои, после которых воркер переподключается или сообщение повторяется, используют Warning. Ошибки окончательной обработки с подтверждённой DLQ — Error. Изменения уровней не меняют правила доставки и подтверждения сообщений.

## Диагностика ошибок бирж

Шлюз пишет одно короткое предупреждение: биржа, операция, код ошибки, HTTP-статус (если известен) и понятная причина. Полные ответы, заголовки и внешний IP не записываются. Повторное сообщение CurrentRates о той же ошибке находится на Debug; сводка цикла по-прежнему содержит Failed. Решение HistoricalRates о повторе/DLQ является отдельным событием.

- Exchange.GeoRestricted: явное сообщение о стране/регионе, включая CloudFront внутри ошибки десериализации.
- Exchange.RateLimited: HTTP 429, тип ошибки клиента RateLimit, код Bybit 10006 либо явное сообщение о частоте запросов.
- Exchange.AccessDenied: HTTP 403 без признаков геоблокировки/лимита; причина доступа не угадывается.
- Exchange.InvalidResponse: ответ не удаётся десериализовать, без более конкретной причины.
- Exchange.Network / Exchange.Timeout: распознанная сетевая ошибка / таймаут, включая вложенные исключения.
- Exchange.UpstreamUnavailable: серверный 5xx или неклассифицированный сбой.

Сообщение ограничено 400 символами, переносы убраны. Известные геоблокировки описываются короткой фразой; тело некорректного JSON/HTML не выводится. Публичный Error.Description остаётся общим. Коды исходного сервера могут отсутствовать: SDK иногда заменяет их своим типом ошибки. Для Bybit retCode дополнительно извлекается из уже захваченного SDK ответа при наличии.

Классификация помогает диагностике, но не доказывает смену IP/VPN. По существующим правилам HistoricalRates распознанные GeoRestricted и Authentication отправляются в DLQ без повторов; текущие ставки снова запрашиваются следующим циклом. Правила retry/ack отдельно не менялись.
